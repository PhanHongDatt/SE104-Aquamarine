1. Tổng quan hệ thống

Aquamarine là hệ thống web hỗ trợ quản lý cửa hàng vàng bạc đá quý. Hệ thống tập trung vào các nghiệp vụ: quản lý danh mục, quản lý sản phẩm, mua hàng, bán hàng, dịch vụ, tra cứu, báo cáo, phân quyền, thay đổi quy định và sao lưu/phục hồi dữ liệu.

Vai trò người dùng

  • Quản lý/Admin: toàn quyền với danh mục, giao dịch, báo cáo, tài khoản, phân quyền và quy định.
  • Nhân viên: thao tác bán hàng, mua hàng, dịch vụ, tra cứu và xem các màn hình được cấp quyền.

Công nghệ sử dụng

  • Frontend/backend: Next.js 14 App Router, React 18, TypeScript.
  • Cơ sở dữ liệu: PostgreSQL thông qua Prisma ORM.
  • Xác thực: NextAuth Credentials Provider.
  • Validation: Zod, React Hook Form.
  • Giao diện: Tailwind CSS, lucide-react, sonner toast.

Sơ đồ điều hướng tổng quát

Đăng nhập -> Dashboard -> Đơn vị tính -> Loại sản phẩm -> Sản phẩm -> Khách hàng -> Nhà cung cấp -> Phiếu mua hàng -> Phiếu bán hàng -> Phiếu dịch vụ -> Tra cứu phiếu dịch vụ -> Báo cáo tồn kho -> Báo cáo doanh thu -> Phân quyền người dùng -> Thay đổi quy định -> Sao lưu và phục hồi dữ liệu

3. Chức năng nghiệp vụ

Nhóm chức năng Mô tả xử lý Ràng buộc chính File xử lý chính
Đăng nhập và phân quyền Xác thực tài khoản, lưu session, phân biệt Quản lý/Nhân viên, chặn route admin. Người chưa đăng nhập bị chuyển về đăng nhập; nhân viên không vào được route admin. auth.ts, middleware.ts, user.action.ts
Danh mục Quản lý đơn vị tính, loại sản phẩm, sản phẩm, khách hàng, nhà cung cấp. Không trùng tên/mã, không xóa dữ liệu đang được giao dịch sử dụng. don-vi-tinh.action.ts, loai-san-pham.action.ts, san-pham.action.ts
Mua hàng Lập phiếu mua, ghi chi tiết, tăng tồn kho, cập nhật đơn giá nhập và giá bán. Số lượng và đơn giá phải lớn hơn 0; thành tiền phải khớp số lượng x đơn giá. giao-dich.ts, purchase.schema.ts
Bán hàng Lập phiếu bán, kiểm tra tồn kho, ghi chi tiết, giảm tồn kho. Không bán vượt tồn; thành tiền và tổng tiền phải đúng. giao-dich.ts, giao-dich.schema.ts
Dịch vụ Lập phiếu gia công/kiểm định, tính đơn giá, thành tiền, trả trước, còn lại. Trả trước đạt tỷ lệ tối thiểu; kiểm định phải có kết quả trước khi giao. service.action.ts, service.schema.ts
Báo cáo Tổng hợp tồn kho và doanh thu theo kỳ, hỗ trợ in báo cáo. Tồn cuối = tồn đầu + mua vào - bán ra; tồn cuối thấp hơn tồn tối thiểu thì cảnh báo. bao-cao.ts, report.service.ts
Sao lưu/phục hồi Sao lưu database ra file SQL, phục hồi từ file backup khi có xác nhận. Restore yêu cầu RESTORE_CONFIRM=YES; file backup không commit lên Git. db-backup.js, db-restore.js

Yêu cầu: Node.js 20+, npm, Docker nếu dùng PostgreSQL bằng container.

cd /home/tofu/SE104-Aquamarine/fe
npm install
cp .env.example .env.local
npm run db:up
npx prisma db push
npx prisma db seed
npm run dev

9. Rủi ro còn lại và đề xuất cải thiện

Rủi ro Mức độ Hiện trạng Đề xuất
Test đăng nhập/phân quyền chưa có E2E tự động Trung bình Mật khẩu đã hash bằng bcryptjs, có phân quyền mềm theo bảng; đã kiểm build/lint nhưng chưa có Playwright. Bổ sung E2E đăng nhập, route guard, tick quyền và đăng nhập lại để xác nhận quyền mới.
Chưa có UI riêng cho sao lưu/phục hồi Trung bình Đã có script CLI. Bổ sung màn hình Admin cho backup/restore có xác nhận.
Test tích hợp DB chưa tự động hóa đầy đủ Trung bình Đã có unit test business rules. Thêm test transaction mua/bán/dịch vụ bằng database test.
Chưa có test E2E trình duyệt Trung bình Đã có hướng dẫn test thủ công. Bổ sung Playwright cho đăng nhập, bán hàng, mua hàng, dịch vụ, báo cáo.
Kết luận: hệ thống đã đáp ứng tốt yêu cầu đồ án về giao diện, chức năng, kiểm thử logic, bảo mật mật khẩu và build. Để vận hành thực tế, cần tiếp tục bổ sung test tích hợp tự động, test E2E và quy trình backup/restore có bằng chứng định kỳ.
